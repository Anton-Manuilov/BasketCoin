# Changelog

## v5 — ограничитель минта (ветка `feat/v5-mint-limits`, кандидат на внешний аудит)

База: аудиторский коммит v4 `ab144a7` (этап B). Изменён только `src/BasketVault.sol`; остальная логика v4 (цены, комиссии,
уровни выкупа, индекс, пауза, таймлок, sequencer) не менялась.

### Добавлено
- **Пол покрытия при минте.** `mint` откатывается `MintCoverageFloor(basketId, coverageAfterBps, floorBps)`, если покрытие
  *после* минта ниже `floorBps` (по умолчанию 150%).
- **Плавное сужение.** При покрытии *до* минта в зоне `[floorBps, taperBps)` (по умолчанию 150–160%) лимиты окна и блока
  умножаются на `(cov − floor) / (taper − floor)` и при покрытии ≤ пола равны нулю.
- **Лимит скорости.** Не больше `hourCapBps` (25%) резерва корзины за окно `MINT_WINDOW` = 1 час (фиксированные окна
  `block.timestamp / 3600`) и не больше `blockCapBps` (10%) резерва за блок. Лимит считается от текущего резерва
  (Σ reserve·min(p,$1)) до минта; учитывается нетто-взнос после комиссии по min(p,$1). Ошибки
  `MintWindowCapExceeded` / `MintBlockCapExceeded(basketId, usdIn, remainingUsd)`.
- **Genesis.** Первый минт в пустую корзину (`totalSupply == 0`) лимитами скорости не ограничен, пол покрытия применяется:
  перед первым минтом нужно пополнить резерв `topUpReserve` (иначе первый минт даёт 120% < 150%).
- `setMintLimits(floor, taper, hourCap, blockCap)` — **только через существующий таймлок** (`scheduleOp` → 2 дня → `executeOp`,
  `PARAM_DELAY`), в жёстких границах-константах: пол 140–200%, `floor ≤ taper ≤ floor + 30%`, час 1–50%, блок 0,1%–час.
  Пол не может быть ниже 140%: минт не способен перевести корзину в STANDARD. Выключить ограничитель нельзя.
- Событие `MintLimitsUpdated(floorBps, taperBps, hourCapBps, blockCapBps)` (также в конструкторе — теперь 8 событий).
- View `mintLimits()`, `mintWindows(basketId)`, `mintCapacity(basketId)` — остаток лимитов окна и блока (для бота/сайта).
- `_reserveUsd(basketId)` вынесен из `_coverageBps` без изменения формулы.

### Не затронуто
`redeem`, `topUpReserve`, `setIndex`, `setWorkingPrice`, пауза, депег, sequencer — ограничитель на них не действует.
Сигнатура конструктора не изменилась (значения по умолчанию выставляются в нём).

### Тесты
- Все 230 тестов v4 проходят в режиме регрессии (`test/utils/V4Mode.sol` выключает ограничитель через `vm.store`).
- Новые: `test/unit/MintLimits.t.sol` (16: таймлок, границы, genesis, блок, окно, сужение, пол, fuzz),
  `test/invariant/MintLimitsInvariant.t.sol` (4 инварианта: пол, лимиты окна/блока, только ожидаемые откаты, покрытие ≥115%).
- Slither 0.11.6: 0 High, 0 Medium; 17 результатов (Low/Informational), см. `docs/AUDIT_PACKAGE/appendix/slither-v5.txt`.

### Известные свойства (для аудиторов)
- Фиксированные часовые окна: на стыке окон возможно до 2× часового лимита за короткое время (ограничено 10%/блок).
- `setIndex` +11% 28-го снижает покрытие; при покрытии ≤150% минт останавливается до пополнения резерва.
- Лимиты не ограничивают выкуп: защита вкладчиков — пол покрытия + полный выкуп (1,2P) при покрытии ≥140%.
